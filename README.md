## Qadam

Платформа бизнес-задач для студентов. Бизнес описывает задачу своими словами, ИИ задаёт уточняющие
вопросы и собирает из черновика и ответов карточку задачи — без выдуманных фактов: если сведений нет,
поле остаётся пустым. Прозрачный рейтинг (без ИИ) показывает, насколько карточка готова и что добавить.
Бизнес вручную публикует задачу, студенческие команды получают рекомендации и откликаются, бизнес
принимает отклики и подтверждает этапы работы (+10 баллов команде).

**Стек:** Java 21, Spring Boot 3, Maven, H2, Swagger UI.

### Быстрый старт

По умолчанию приложение работает в mock-режиме: LLM не вызывается, ключ OpenAI не нужен.
Mock-ИИ детерминированно раскладывает предложения черновика по полям карточки и ничего не выдумывает.

**Вариант 1. Docker Compose** (нужен только Docker):

```bash
docker compose up --build
```

Контейнер считается здоровым, когда отвечает `GET /api/health`. Остановить: `docker compose down`.

**Вариант 2. Maven Wrapper** (нужен JDK 21 или новее):

```powershell
.\mvnw.cmd spring-boot:run      # Windows
```

```bash
./mvnw spring-boot:run          # Linux / macOS
```

После запуска:

- Health check: http://localhost:8080/api/health
- Swagger UI: http://localhost:8080/swagger-ui.html

**Режим OpenAI.** Скопируйте `.env.example` в `.env` и укажите:

```dotenv
LLM_MODE=openai
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
```

`docker compose` читает `.env` автоматически. При запуске через Maven задайте те же переменные
в окружении (например, `$env:LLM_MODE="openai"; $env:OPENAI_API_KEY="sk-..."`).
Без ключа в режиме `openai` приложение не стартует. `.env` в git не коммитится.

Сборка и тесты: `.\mvnw.cmd clean verify`. Тесты работают без сети, отчёт о покрытии —
`target/site/jacoco/index.html`.

При старте в пустую базу добавляются синтетические демо-данные: 5 черновиков разной полноты,
5 опубликованных задач всех четырёх уровней рейтинга, 5 команд и 5 откликов.
Отключить: `$env:DEMO_DATA_ENABLED="false"`.

### Рейтинг карточки

| Критерий               | Баллы | Правило                                                          |
|------------------------|-------|------------------------------------------------------------------|
| Контекст и потребность | 20    | контекст 10 + потребность 10                                     |
| Данные и материалы     | 20    |                                                                  |
| Ожидаемый результат    | 15    |                                                                  |
| Критерии успеха        | 15    | полный балл, если есть число или процент; иначе 7                |
| Ограничения            | 10    |                                                                  |
| Пользователи           | 10    |                                                                  |
| Связь с бизнесом       | 10    | контакт 5 + формат взаимодействия 5                              |

Поле засчитывается, если в нём не меньше 15 символов (контакт — не меньше 5).
Уровни: `DRAFT` 0–39 (в каталоге с пометкой «требует уточнения»), `WORKING` 40–69, `READY` 70–89,
`PRIORITY` 90–100. Рейтинг пересчитывается при каждом изменении карточки.

### API

| Метод и адрес                                 | Что делает                                                              |
|-----------------------------------------------|-------------------------------------------------------------------------|
| `POST /api/tasks/analyze`                     | `{draftText, industry}` → недостающие поля и не меньше 3 вопросов       |
| `POST /api/tasks`                             | `{draftText, industry, answers: [{field, answer}]}` → задача `DRAFT`   |
| `GET /api/tasks/{id}`                         | задача с полями карточки и рейтингом                                    |
| `PUT /api/tasks/{id}/card`                    | правка карточки, пересчёт рейтинга                                      |
| `POST /api/tasks/{id}/publish`                | ручная публикация (`PUBLISHED`)                                         |
| `GET /api/catalog?industry=&level=`           | опубликованные задачи по убыванию рейтинга                              |
| `GET /api/industries`                         | отрасли: код и название                                                 |
| `GET /api/teams`                              | команды                                                                 |
| `GET /api/teams/{id}/recommendations`         | задачи уровня от `WORKING` по совпадению навыков и интересов команды    |
| `POST /api/tasks/{id}/proposals`              | отклик `{teamId, idea, plan, duration, prototypeUrl}`, только на опубликованную задачу |
| `GET /api/tasks/{id}/proposals`               | отклики на задачу                                                       |
| `POST /api/proposals/{id}/accept`, `/reject`  | решение бизнеса по отклику                                              |
| `POST /api/proposals/{id}/confirm-milestone`  | подтверждение этапа, команда получает +10 баллов                        |

Ошибки возвращаются в едином формате с сообщением на русском:

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "Задача с id=42 не найдена",
  "timestamp": "2026-09-23T10:15:30Z"
}
```

Коды: 400 — ошибка валидации (с полем `fieldErrors`), 404 — не найдено, 409 — действие недоступно
(например, отклик на неопубликованную задачу), 502 — ИИ не смог обработать задачу.
